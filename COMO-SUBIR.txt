NETLIFY / AUTODEPLOY

Produção: branch main, https://intranet.centeronibus.com.br.
O build publica dist/ e as funções de netlify/functions/.
As funções guardam auditoria e conteúdo no Netlify Blobs. A IA usa
processamento em segundo plano e verificação agendada a cada hora.
Configure os segredos no Netlify, somente em production:
BADGE_SECRET_B64, OPERATORS_JSON, SETTINGS_KEY, PUBLIC_ORIGIN, CENTER_ENV.
Veja README.md para detalhes. Nunca suba .env ou chave-emissao.json ao GitHub.

MODO LOCAL / PUBLICAÇÃO SOMENTE ESTÁTICA

PUBLICAÇÃO — ECOSSISTEMA CENTER ÔNIBUS v3

Consulte README.md para configuração completa.

1. Rode python build/build.py para gerar as páginas e a pasta dist/.
2. Para cartão, editor de e-mail e validação pública, publique apenas dist/.
   Netlify já está configurado para essa pasta. Não publique a raiz inteira
   do checkout depois de configurar .env ou dados privados.
3. Emissão rastreada, auditoria, IA e blog exigem o servidor Node.js 24+.
   Configure .env a partir de .env.example, credenciais individuais,
   chave privada existente e SETTINGS_KEY. Execute:
     node --env-file=.env server/index.mjs
4. Em produção, use HTTPS, processo supervisionado e disco persistente.
   Sirva páginas e API na mesma origem. Configure PUBLIC_ORIGIN.
5. A chave OpenAI/Google pode ser conectada no módulo Assistente de conteúdo
   após entrar com credencial de administrador.

Os QR novos apontam para /v/ do domínio do portal. Para outro endereço,
configure VALIDATOR_URL no ambiente durante o build. Preserve a rota antiga
para os crachás já impressos.

A chave privada não está no GitHub. O campo sec_b64 do arquivo que está
com o RH deve ir somente para BADGE_SECRET_B64 no servidor.
Quem mantiver uma cópia antiga da privada ainda consegue emitir por fora;
impedir isso exige rotação do par e reemissão dos crachás.

Este repositório não contém o CMS do site principal da Center.
O blog será servido em /blog/ no domínio onde este servidor for instalado.
